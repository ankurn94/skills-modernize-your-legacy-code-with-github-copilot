# Student Account Application Test Plan

This plan describes the current COBOL application's observable behavior and
account rules. Run each scenario in a fresh application process unless the
pre-condition says to build on earlier transactions. Results are blank for
execution; record observations and stakeholder decisions before using these
cases as acceptance criteria for the Node.js implementation.

| 1. Test Case ID | 2. Test Case Description | 3. Pre-conditions | 4. Test Steps | 5. Expected Result | 6. Actual Result | 7. Status (Pass/Fail) | 8. Comments |
|---|---|---|---|---|---|---|---|
| ACC-001 | Initialize a new account | Application is not running. | 1. Start the application.<br>2. Select **View Balance**. | The account balance is initialized to **1000.00** and displayed. | Not run | Not run | Confirms `DataProgram`'s initial working-storage value. |
| ACC-002 | Display current balance | Application is running with a new account and no transactions. | 1. Select **View Balance**. | The current balance is displayed as **1000.00** and remains unchanged. | Not run | Not run | Covers the menu dispatch, `READ`, and balance display. |
| ACC-003 | Credit a positive amount | Application is running with a balance of **1000.00**. | 1. Select **Credit Account**.<br>2. Enter **50.00**.<br>3. Viewing the balance also shows **1050.00**. | Not run | Not run | Confirms amount addition and that the update is stored for subsequent operations in the same run. |
| ACC-004 | Credit a fractional amount | Application is running with a balance of **1000.00**. | 1. Select **Credit Account**.<br>2. Enter **0.01**.<br>3. | ACC-005 | Credit zero | Application is running with a balance of **1000.00**. | 1. Select **Credit Account**.<br>2. Enter **0.00**.<br>3. | ACC-008 | Reject a debit greater than the balance | Application is running with a balance of **1000.00**. | 1. Select **Debit Account**.<br>2. Enter **1000.01**.<br>3. | ACC-009 | Debit zero | Application is running with a balance of **1000.00**. | 1. Select **Debit Account**.<br>2. Enter **0.00**.<br>3. | ACC-010 | Apply multiple operations to the same account | Application is running with a new balance of **1000.00**. | 1. Credit **50.00**.<br>2. Debit **20.00**.<br>3. | ACC-012 | Exit the application | Application is running at the menu. | 1. Select **4**. | The menu loop ends and the application displays its goodbye message. | Not run | Not run | Confirms normal termination. |
| ACC-013 | Verify account state is not durable | Application is running with the balance changed from **1000.00** (for example, credit **50.00**). | 1. Exit the application.<br>2. | ACC-014 | Read and write stored balance through the data interface | Application is running. | 1. Use a balance read (for example, select **View Balance**).<br>2. | ACC-016 | Confirm behavior at the amount/balance capacity | Application is running with a balance of **1000.00**. | 1. Attempt a credit that would make the balance exceed **999999.99**.<br>2. The Node.js implementation rejects the credit, displays a maximum-balance message, and leaves the balance unchanged. Confirm this added safeguard as an acceptance rule with stakeholders. | Not run | Not run | The COBOL fields allow six integer digits and two fractional digits. |
